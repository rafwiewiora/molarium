# Debugging episode: 2D editing and orientation continuity

- **Date:** 2026-08-20
- **Status:** fixed and regression-tested
- **Area:** synchronized 2D/3D molecular editing

## Trigger

The first 2D panel displayed the molecule but did not behave like an editor.
The user reported:

> "can't change anything in 2D until I click on e.g. select but that changes the main mode to build and still cna't do anything in 2D, only 3D"

After toolbar activation was repaired, atom picking still required implausibly
precise clicks:

> "it's clunky, I think requirement to click very exactly on an atom in 2D is making it hard"

Once fuzzy picking worked, a new continuity defect became visible. Editing LSD
changed the apparent orientation of the 2D drawing between the before and after
states:

> "before mod, after - 2D rotates"

This was not cosmetic. A rotating depiction makes it harder to see which local
chemical change the user just made.

## Diagnosis and changes

1. The 2D toolbar was not activating its own edit state. This was corrected in
   commit `fa02068` (`Fix 2D editor toolbar activation`).
2. SVG atom picking used the exact RDKit atom coordinate. The hit test was
   changed to use a forgiving nearest-atom target while preserving the identity
   mapping into the 3D model. This was committed as `d4aba0f` (`Make 2D editing
   clicks forgiving`).
3. Each chemistry edit asked RDKit to make a fresh depiction. Even when the
   chemical graph changed locally, RDKit could choose a new fit, translation,
   scale, or orientation for the whole drawing. The current fix carries the
   previous RDKit mol block into `generate_aligned_coords`, matches surviving
   atoms by object identity, and applies a no-reflection screen-space similarity
   transform. The intended invariant is that unchanged atoms remain visually
   stationary while the edited neighborhood changes.

The third change is intentionally tested at the screen-coordinate level. Merely
preserving molecular coordinates is insufficient if the SVG viewport then fits
the result differently.

## Validation

The browser regression loads `CC(O)c1ccccc1`, records the screen positions of
the retained atoms, performs a 2D atom edit, and measures their post-edit RMSD.
It also exercises fuzzy atom and bond clicks, bond-order edits, atom insertion,
selection synchronization, finish/discard behavior, and 2D/3D topology parity.

Run:

```sh
bun run test:2d
bun run build:web
```

The orientation regression passes when all surviving atoms are recovered and
the centered screen-coordinate RMSD of the unchanged ring remains below 8
pixels. On 2026-08-20, `bun run test:2d` passed all 16 browser checks. A common
panel translation is allowed because opening Build controls can move the
floating panel; rotation and rescaling of the molecular core are not.

## Evidence and limits

The before/after screenshots and exact surrounding conversation remain in the
private Codex rollout. They are not copied here because the raw session can also
contain credentials and unrelated private context. A publication figure should
be exported separately after manual cropping and review.

The alignment assumes enough unchanged atoms to define a stable 2D transform.
Large graph rewrites may legitimately require a new depiction. Future tests
should cover symmetric molecules, deletion of the anchoring atoms, fused rings,
and edits that change the maximum common subgraph.
